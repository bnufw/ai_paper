# brainstorm: year-based paper search index and history

## Goal

将论文搜索从“单会场优先、多会场最新补充”调整为“年份优先”。用户选择年份后，可以看到该年份下已有数据的会议，搜索复用已获取论文数据和已构建索引，避免重复拉取论文或重复构建索引，并保存搜索记录用于回看。

## Background / Known Context

* 现有后端按 `venue_year` 存储论文数据：`storage/search/papers_data/<Venue>_<Year>/all_papers.json` 和 `metadata.json`。
* 现有后端按 `venue_year` 存储 Chroma 向量索引：`storage/search/vector_db/<venue>_<year>/`。
* `/api/venues` 返回所有支持会议，并在 `status` 中暴露每个会议已获取、已索引的年份。
* `/api/search` 只搜索单个 `venue + year`。
* `/api/multi-search` 支持传入多个 `venue + year`，但前端当前多会场模式固定使用 `auto_latest: true`，即每个会议选择本地最新年份。
* 当前前端数据准备区先选会议再选年份；搜索区有“单会场”和“多会场最新”两个模式。
* 当前本地已有数据包括 `NeurIPS_2025`、`AAAI_2026`，并已存在对应向量索引。
* 搜索导入相关模块中未发现持久化搜索记录模型。

## Assumptions

* “按年份搜索”表示先选择年份，再在该年份下选择或默认使用已有数据的会议。
* 已建立数据默认视为稳定资产，普通搜索流程不触发重新获取论文或重建索引。
* 首次获取论文、首次构建索引保留在数据准备区；已完成数据不提供重建入口。

## Requirements

* 年份和会议都作为搜索筛选项展示，年份支持像会议一样多选。
* 搜索区年份选项只显示已有本地数据的年份。
* 搜索区默认选中本地可用的 `2025` 和 `2026`，缺少这两个年份时回退到最近本地数据年份。
* 选择年份后展示所选年份下已有数据的会议，以及每个会议在所选年份中的已获取、已索引状态。
* 搜索默认选中所选年份下已索引的会议，并允许用户取消个别年份或会议。
* 搜索区不再提供“单会场 / 多会场最新”模式切换。
* 有论文数据但缺少向量索引的会议需要展示，但默认不参与年份搜索。
* 搜索应复用已有论文数据；已存在索引时优先使用向量检索，缺少索引时按现有逻辑降级到关键词检索。
* 搜索流程不得自动重新获取论文数据。
* 搜索流程不得自动重建向量索引。
* 已获取并已索引的数据在界面中视为固定资产，不展示重新获取或重建索引按钮。
* 缺少数据的年份或会议仍允许通过数据准备区首次获取论文并构建索引。
* 数据准备区也采用年份优先：先选年份，再显示所有支持会议的获取和索引状态。
* 搜索多个会议年份组合时，“返回数量”表示所有选中组合合并排序后的全局 `TopK`。
* 多会议搜索中任一选中会议失败时，整体搜索视为失败，不保存成功部分的搜索记录。
* 搜索记录保存到浏览器 IndexedDB。
* 搜索记录需要包含查询内容、年份集合、参与会议、搜索配置、结果摘要、创建时间和当次可见结果列表。
* 搜索记录列表放在搜索导入页内部。
* 点击搜索记录后恢复当次保存的查询、会议、配置和结果快照，不重新执行搜索。
* 搜索记录只保留最近 10 条，支持删除单条记录和清空全部记录。

## Acceptance Criteria

* [ ] 年份支持多选，默认选中本地可用的 `2025` 和 `2026`。
* [ ] 年份选择后展示所选年份下可用会议列表。
* [ ] 搜索区年份选项不显示完全没有本地数据的年份。
* [ ] 已获取但未索引会议可见，默认未选中。
* [ ] 搜索入口可以按多个年份和多个会议组合搜索，不再依赖“多会场最新”。
* [ ] 搜索区不存在“单会场 / 多会场最新”模式切换。
* [ ] 搜索期间不会调用获取论文接口。
* [ ] 搜索期间不会调用构建索引接口。
* [ ] 已获取并已索引的数据不显示重新获取或重建索引操作。
* [ ] 缺少数据的会议年份仍可通过数据准备区首次建立。
* [ ] 数据准备区先选年份，再展示所有支持会议状态。
* [ ] 多会议年份组合搜索结果总数不超过用户设置的返回数量。
* [ ] 任一选中会议搜索失败时展示整体失败，不创建搜索记录。
* [ ] 搜索完成后生成一条可回看的搜索记录，且记录包含当次可见结果列表。
* [ ] 搜索记录在页面刷新后仍存在。
* [ ] 搜索记录列表在搜索导入页内部可见。
* [ ] 点击搜索记录后恢复当次结果快照，且不会触发新的搜索请求。
* [ ] 搜索记录超过 10 条时自动保留最近 10 条。
* [ ] 支持删除单条搜索记录和清空全部搜索记录。
* [ ] 现有获取论文、构建索引、导入论文能力保持可用，除非后续明确缩减范围。
